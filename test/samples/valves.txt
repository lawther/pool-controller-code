# Valves: the pool/spa valve actuators, driven by the Connect 10 from the CMD
# 0x14 mode broadcast - then the valve zones - CMD 0x25 (Valve Sync) and CMD
# 0x27 (Valve State Broadcast) - further down.
#
# The actuator section is excerpted from live captures on lawther's install: a
# Connect 10 with its two actuators on the inlet/outlet sockets, nothing on
# Valve 1/Valve 2, and an ICI gas heater plumbed to the spa. Captures 1-3 were
# stimulated by selecting a mode in HA via MQTT.
#
# The burst, in order:
#
#   0x15  Mode Toggle Command     the mode switch itself
#   0x14  Mode                    the Touchscreen confirming the new mode - this
#                                 is what the Connect 10 moves the valves on
#   0x27  Valve State Broadcast   valve *zones* - a different subsystem, see below
#   0x1A  Heater Toggle Command   only when the new mode needs the heater
#   0x41  Heater Target State     switched; see heater_commands.txt
#
# No frame reports where the actuators are. See PROTOCOL.md command 0x14.
#
# Idle broadcast traffic between the bursts has been dropped. Timestamps are
# from the original captures, so the gaps are real.

# 0x27 is the Valve State Broadcast, which reports the user-configurable valve
# *zones* - the auxiliary "Valve 1" and "Valve 2" actuator sockets.
#
# On this system, 0x27 appears exactly once per capture - after 0x14/0x15, and before
# any 0x1A. The Touchscreen appears to republish valve state as a step of the sequence.
#
# This install has no zones configured, so that republish carries a slot
# count of zero and no slot entries. Do not read it as "the valves are idle" -
# the combo actuators are a different subsystem and are never reported here at
# all.

# Valve zones being configured and switched (CMD 0x25 Valve Sync and CMD 0x27
# Valve State Broadcast). Excerpted from two round 14 captures on a different
# install, where Valve 1 was configured and switched On then Off, and later
# Valve 2 was configured with Auto enabled and cycled through Auto and On.
#
# 0x27 is a slot count followed by one {configured, state, active} entry per
# slot. It sits at zero slots until the first zone is configured, then jumps
# straight to the full two slots - the unconfigured slot is sent as 00 00 00.
# 0x25 is the matching active-valves bitmask (bit 0 = Valve 1, bit 1 = Valve 2)
# sent to Internal Channels ~130 ms before the 0x27, in the Touchscreen's status
